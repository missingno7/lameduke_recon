# Which function actually lost its match?

Only MENUES reproduces the premise that an ordinary C edit makes a whole function STRICT and removes STRICT from another. SECTOR and ENGINE reproduce specific register choices while their target functions get worse. GAME includes a two-byte improvement in a NEAR caller, two genuine losses in a different experiment, and a caller-only edit. Treating all four as exchanges of STRICT byte counts would misprice three of them.

**Outcome.** No stock source tested made a requested target and its affected peers simultaneously STRICT. The strongest new source candidate keeps every previously STRICT MENUES function and leaves four stack displacements in `draw_and_probe`. The SECTOR and ENGINE positive controls separately restore the lost peer proofs while the edited target stays NEAR. ## SECTOR — coupled-but-solvable boundary

**PROVEN.** The case-406 edit reads `nextspritestat[i]` before writing `hittype[i][0]`. In the stock allocator the case-405 conversion t116 and scale t117 both have savings 564. The baseline visits the conversion before the scale (archived ranks 97, 110). With the prefetch, the scale precedes the conversion (82, 83). Both choose ECX in place of EAX. This fixes case 405. Across the full 1,740-byte extent, `checkhitswitch` goes from **2 differences, first +374, zero fixup problems** to **299, first +93, 37 fixup diagnostics**. Its 108-byte leading table is included in both results. The prefetch also changes the order of a memory read relative to a store, so it should not be inferred as the original merely from the winning register pair. [Baseline](current/sector/base/dos.txt) · [Prefetch](current/sector/prefetch/dos.txt) · [Archived ranks and source controls](../blockers/natural/RULES.md)

`checksectors` calls `checkhitswitch(target)` in C. Its compiled expansion participates in the caller's allocation. The caller's frame goes **176 → 164 bytes**, and its public span goes **11,184 → 11,072**. As a deletion control, replacing the callee definition with its declaration in either source produces the same reduced C. Its object has an explicit self-relative `checkhitswitch_` call at extent +2a9d and a 42-entry leading table instead of 66. The full objects have the 66-entry table and no such external call. [Caller trace before](current/sector/base/traces/checksectors.json) · [After](current/sector/prefetch/traces/checksectors.json) · [Declaration control](current/sector/switch-declared/dos.json)

The **856 actual ceiling bytes, all 40 references, 104 colour decisions, 16-byte frame and final homes agree**. The table occupies the 264 bytes from `1:1c4d8` to the entry at `1:1c5e0`. It is physically in the preceding OMF public span, and the verifier charges it to `checksectors`. To certify where `checkhitceiling` ends, the oracle must confirm that table. Its greatest destination is at caller PUBLIC+2b9c, requiring a span of at least **11,165 bytes**. Twenty oracle entries fall outside the current prefetch span. The sole lost ceiling obligation is the end boundary. On the older snapshot the span fell to 11,056, 21 entries fell outside, and `checksectors` worsened 7,670 → 8,118 differences. On the current snapshot it worsens 7,135 → 7,473. [Table and body measurements](ledger.json) · [Ceiling trace before](current/sector/base/traces/checkhitceiling.json) · [After](current/sector/prefetch/traces/checkhitceiling.json)

**Positive control.** Keep the identical prefetch and change only `checksectors`: cache the initial sector index in its existing `target` and pass the near-lift arguments directly. The stock DOS public span becomes **11,216**, all 66 oracle destinations fit, and `checkhitceiling` returns to STRICT. The standalone switch retains the same 299 differences. The caller now has 8,127 differences and an unverified end, so this is a causal control. Thirty case-loop spellings and thirty caller controls were tried. The two-byte canonical switch remains the better target. Nothing in these tests implicates the source of `checkhitceiling`. The outstanding source problem is getting the switch's two ECX uses with the rest of its standalone and expanded code intact. ## MENUES — two outputs from the same shade conversion

**PROVEN.** The long `s` formal gives a STRICT 352-byte standalone `menutext`. In its expansion inside `draw_and_probe`, Watcom widens the incoming shade before the dimension-mode test. The oracle reads the shade byte after that test. The byte formal produces the oracle order and all **896 bytes, fixups and extent** of `draw_and_probe`. The standalone function keeps its 16-byte frame. CG95 shows `start_x` moving from home −4 to −12 and `ac` from −12 to −4, with `base_shade` fixed at −8. Final code swaps ESP+0c and ESP+04 in six displacements, first **+1f**. All references and all 5,216 bytes of `menus` remain verified in the simple byte-formal edit. Its net gain is 544 STRICT bytes. This explains why either function alone underdetermines the formal and local spelling. [Long-form DOS](current/menus/base/dos.txt) · [Byte-form DOS](current/menus/byte/dos.txt) · [Allocator projections](allocator.json)

**Which definitions matter?** A five-definition DOS reduction keeps `menutext`, `probe`, `draw_and_probe`, `draw_menu_slider` and `menus` with original headers, data and order. It reproduces both versions' target verdicts. On the byte version each one-definition deletion of a peer breaks the caller proof. Removing `menutext` leaves a 588-byte caller, removing `probe` leaves 496 bytes, removing `menus` leaves a 895-byte exact prefix with an unverified end, and removing the slider leaves all 896 caller bytes equal with an unconfirmed table boundary. The reduced `menus` itself is only CODE_BYTES_MATCH. These witnesses justify the five definitions for this deletion test and this public, without establishing a globally minimal source. [Five-definition object](current/menus/byte-five/dos.txt) · [Without slider](current/menus/byte-withmenus/dos.txt) · [Without menus](current/menus/five-minus-menus/dos.txt) · [Without probe](current/menus/five-minus-probe/dos.txt) · [Without menutext](current/menus/five-minus-menutext/dos.txt)

**Non-regressing source.** Keep the byte formal and name the widened character inside the lowercase arm, `long glyph = *t; ac = glyph + 26;`. This restores standalone `menutext` and keeps `menus` STRICT. It leaves six stack displacements in the direct caller. Declaring the four existing locals in the order `shade, ac, base_shade, start_x` removes two of the six. The full DOS unit now retains **all ten existing STRICT functions (8,634 B)**, and `draw_and_probe` drops from **395 differences and 16 fixup diagnostics to four differences, first +88, all 45 references verified**. The extent is still 896 bytes. At instruction starts +85, +a0, +c6 and +f5, the displacement bytes address ESP+30h/28h/30h/28h; the oracle has +28h/30h/28h/30h. CG95 gives the inlined cursor and base shade homes ?4 and ?12; swapping those two would agree with the oracle. Both give `start_x` ?8, `ac` ?16 and a 52-byte frame. The cleaned candidate and the search witness produced byte-identical DOS objects. This supplies direct evidence that a byte formal is compatible with standalone `menutext` and the menu-page expansions. The remaining source constraint is the direct caller?s two stack homes. ## ENGINE — wrong reconstruction of the full predicate context

**PROVEN.** The March 1995 direct-expression donor gives t92/scale EDX and t91/signed link EDI in backend block 26. The December baseline gives EAX and EDX. The donor then uses EAX for the right-screen bound where December uses EDX. Its later `spritesortcnt` load uses a six-byte EDX encoding in place of the five-byte EAX load at +29f. The public grows **756 → 757**. The 7-byte baseline (first +12a) becomes 64 differences (first +10), eight fixup diagnostics and an unverified end. The early branch displacement anticipates the later width difference. This is direct source ancestry and a local allocation witness. It does not reproduce December's full instruction stream. [Baseline trace](current/engine/base/traces/scansector.json) · [March trace](current/engine/march/traces/scansector.json) · [DOS verifier](current/engine/march/dos.txt)

**All 11 losses, totaling 13,440 previously STRICT bytes, have a mechanical explanation.** Each differing instruction jumps to another public's shared return sequence. The destination remains at the same offset within its owning public. A relative displacement changes by `movement(destination) − movement(instruction)`. Below, each sign is that change in bytes. The operand audit accounts for every changed byte in the eleven common spans. The physical span of `transmaskvline` also contracts from 604 to 603 at the alignment boundary, absorbing the one-byte shift for later publics. Stock `drawrooms` and `transmaskvline` traces preserve all their colours and frame homes. [Operand-by-operand evidence](engine-branches.json) · [Trace projections](allocator.json)

## GAME — shared inlining, unavoidable-for-now for the three whole targets

**PROVEN.** The source experiment responsible for the quoted `strget/main/dobonus` changes is one edit in `gametext`: its newline arm spells `y += 16` as `advance = 16; y += advance`. All 256 standalone bytes and its own final named homes survive. In `nonsharedkeys` each inlined text call has separately allocated glyph and line-origin temporaries. The actual homes for glyphs t160/t190/t218 go **−20/−12/−8 → −20/−24/−12**. The 36-byte frame is preserved. `nonsharedkeys` goes **14 → 12** in 2,080 bytes, first +4d0, with all references verified. In `strget`, the second origin/glyph go **−20/−24 → −16/−20**. Its frame stays 40 bytes. The traces for `main` and `dobonus` also change allocations with unchanged frame capacities. All three were NEAR before this edit. [Changed source](current/game/newline/game.c) · [Whole-unit DOS](current/game/newline/dos.txt) · [Caller and helper traces](allocator.json)

The archived debugger-forced sort orders are positive evidence about the allocator only. ## Source evidence and trade policy

A final 228 MENUES variants staged the actual cursor, signed vertical offset, initial shade, origin, character or glyph advance in the three closest source contexts. None yielded a joint match. The four-byte candidate has no missing fixup sites, target problems or unverified references. Recovering the ideal positions by changing the cursor/base-shade lifetimes remains open. The verdict “unavoidable-for-now” describes this measured search limit. It does not assert an impossible original source configuration. [Final pair probes](current/menus/last.json)

The March 1995 ENGINE source is the same-name compiled donor for `scansector`. For GAME and MENUES, the later Duke 1.5 font, menu and quote code supplies character and argument conventions. Ken's GAME.C supplies ancestry for the key handling. For SECTOR the baseline switch and the archived prefetch supplied the near-exact starting C. None of these donors determines the December local declarations. Pre-edit SemIR classified the canonical switch, `operatefta` and `displayhighscores` as allocation-only. It reported an unsupported comparison for `draw_and_probe` and `nonsharedkeys`; the DOS, OMF and trace controls above establish their particular differences. OMF comparisons also found identical non-CODE segment sizes and contents in each of the four principal before/after pairs. There is no observed change in string pooling or initialized data explaining these trades. [Donor lookup](donors.txt) · [SemIR, GAME](game_game-semir.json) · [SemIR, MENUES](game_menues-semir.json) · [SemIR, SECTOR](game_sector-semir.json) · [SemIR, ENGINE](engine-semir.json)

**Recommendation.** Retain integrator-only acceptance for trades. Count a gain only when the stock DOS source makes the entire extent STRICT. In the decision record, distinguish a changed instruction from a lost boundary and a moved relative field from changed local allocation. Include NEAR peers that get materially worse. For SECTOR and ENGINE, editing the affected bystanders would attack a symptom. For GAME, gate a shared helper on each distinct expansion and on the full TU. For MENUES, the four-byte non-regressing source is a better starting point than trading away the standalone font match. There is no evidence here of incompatible requirements in the original 1994 program.

## Reproduction

Run the following at the repository root. The first command stages the headers and compiles one DOS unit at a time through `wcc.compile_c`, using worker-local scratch and the unchanged DOS guest path. The second command independently runs the stock verifier on a saved object. Exit 1 means the unit still contains a non-STRICT public. The observer compares its unmodified NT code/public/fixup projection with both an ordinary NT build and the saved DOS object. No overlay was used.

```powershell
python -B build/workers/trades/lab.py initial sector/old sector/current engine/old engine/current menus/current game/old game/current
python -B build/workers/trades/lab.py build menus current/menus/proposal/menues.c
python -B tools/match.py --obj build/workers/trades/current/menus/proposal/dos.obj
python -B build/workers/trades/evidence.py
```

The `base` directories contain the frozen headers. For each full control the adjacent `dos.txt`, `dos.json`, `dos-segments.json` and `dos.obj` are the readable verdict, complete verifier rows, segment report and original compiler output. Current and historical replays are kept separately. Raw allocator traces are under the corresponding case's `traces/` directory.
