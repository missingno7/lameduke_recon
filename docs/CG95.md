# Watcom 9.5b allocator tracing

The tools observe the native i386 `BINNT/WCC386.EXE` from `C:/tools/watcom-9.5b` with SHA-256 `8120ccd90e6cdfdcfebca3ef647e8a4489618a12d1548a43cd7fbae75e110956`. `cgtrace95.py` launches a verified scratch copy through `tools/wcc.py`. It uses WOW64 hardware execute breakpoints and reads compiler memory. The observer writes debug registers and the resume flag to manage breakpoints. The compiler image, compiler data, and generated object remain untouched by the observer.

The trace is checked against a fresh ordinary NT build and, by default, a fresh canonical DOS build. Both checks require equality of CODE bytes, coverage, publics, and OMF fixups with their symbolic targets. The log records full NT OMF identity as well. In the SOUNDS controls, the CODE projection agreed and full NT OMF identity failed. The repository already documents host-dependent NT non-CODE padding. The DOS object in each run remains the input to the unmodified `match.py` verifier.

## Reproduce

Run from the repository root with 64-bit Python on Windows.

```powershell
$w = 'build/workers/cg95'
python -B "$w/tools_proposed/cgtrace95.py" --unit engine spritewallfront --out "$w/runs/spritewallfront.json"
python -B "$w/tools_proposed/explain95.py" "$w/runs/spritewallfront.json" --out "$w/runs/spritewallfront-explain.json"
python -B "$w/validate.py"
python -B tools/match.py --obj "$w/runs/spritewallfront-improved.obj" spritewallfront
```

Supply a positional source path before the function name to trace a worker source copy. `--unit` supplies the registered flags and includes. For an unregistered file use `--profile` and `-i` as needed. The trace and the adjacent object carry a SHA-256 link. `explain95.py --reference` compares a second source spelling's trace and verifier verdict. `--symbols` takes a standard repository overlay. The engine and control runs use the canonical symbols directly.

## Breakpoints and recovered decisions

All addresses in this table are compiler PE RVAs.

| RVA | Observed state |
| --- | --- |
| `3748d`, `4703c` | Frontend procedure name after the symbol-name call and corresponding backend release. Scope follows the compiler's reported name and checks the procedure handle on exit. |
| `306e2` | Frontend symbol record after the 46-byte copy. The debugger reads names without invoking compiler functions. |
| `4c22d`, `4c26a` | Actual linked-list input and output of the sorter. The traced comparators are `3ce14` for candidates, `53951` for conflicts, and `4d5bc` for stack homes. |
| `52ff6`, `5300f`, `53049`, `53061`, `530df`, `53116` | Leaf register choices, tested masks, interference and exclusions, eligibility, score, tie disposition, cost check, and returned mask. Conflict endpoints carry backend block and instruction ordinals where they can be decoded. |
| `3eff9`, `5e177` | Temp homes after allocation and after frame fixup. The shareable slots therefore remain visible in the log. |

**PROVEN.** The usual sorter uses repeated gap comparisons with a halving gap and an alternating rounding term. It can move equal-priority items when other records cross them. Conflicts sort by descending savings. Home priority uses a flag and size, with alias offsets as a further order only for the same temp ID. The Python replay reproduced all 47 captured sort orders across the 10 validation traces. The leaf colour loop prefers the highest score and keeps the incumbent on a tie unless the challenger was already used and the incumbent was not. The trace keeps both failed register choices and the final spill or assignment.

**Evidence limit.** The DOS executable supplies emitted register and stack usage. Its original allocator state has to be inferred. The explainer uses reachable instructions, bound relocations, capped local alignment, contemporary compiler decisions, and a small set of identifiable allocation patterns. It reports the verifier's first byte separately from the first attributable machine decision. A forward branch displacement can precede the machine change that stretched its target. Later scheduling, register substitutions, and unusual instruction patterns can prevent a unique anchor. The current hooks cover the main allocator phases used by the tested 9.5b profiles. The tools do not simulate the later scheduler or all late code rewrites.
