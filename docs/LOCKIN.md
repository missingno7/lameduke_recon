# Can a STRICT spelling block its neighbours?

**Yes for individual operands. No tested replacement converted a current NEAR neighbour to STRICT.** The clearest case is PLAYER. Two spellings of `shoot` reproduce all 1,728 bytes of the public. Grouping its locals in an order supported by later Duke source fixes five stack operands inside `processinput`, but loses six previously exact operands. ACTORS gives the opposite result. Its `moveweapons` output pointer is a genuine source-quality defect, yet deleting that entire body from the translation unit leaves every other public’s verifier result unchanged.

**Integration result: 0 additional STRICT functions, 0 additional STRICT bytes, no proposed source changes.** No measured gain warrants a trade. The ranked numbers below are distinct exposed oracle extents per helper. Only the local effects described beside them were demonstrated. Adding those extents together would count some callers several times.

## The call-site width matters

**ACTORS `findplayer`.** SECTOR defines a 160-byte STRICT function returning `short` and writing through `long *`. Changing the definition and SECTOR declaration together to return `int` loses its own proof (26 unequal bytes). In the opposite direction, importing the short return into current ACTORS loses `movefta` (416 B) and `moveweapons` (1,456 B). It changes `moveactors` from 3,125 to 6,799 differences and `moveexplosions` from 74 to 2,648. Keeping the ACTORS return at `int` and removing the argument prototype reproduces the **entire ACTORS DOS object** on both snapshots. At moveweapons +0x31 the oracle saves EAX immediately after the call. The short-return candidate inserts CWDE. An old-style caller is therefore compatible with the evidence. A uniform short-return header for these source bodies fails on both sides. The later Duke header uses a short return and a different first parameter. [ACTORS original](refresh/runs/game_actors/base/dos.json) · [Caller with short return](refresh/runs/game_actors/findplayer/dos.json) · [Old-style caller](refresh/runs/game_actors/old/dos.json) · [Defining-unit control](runs/game_sector/owner-return-findplayer/dos.json).

**ACTORS distance storage.** A four-byte write to a declared two-byte C object is a source defect even when Watcom reserves four bytes on the stack. A union containing a real `long` output and a signed low word gives the correct 1,456-byte extent and verifies every reference, but leaves 17 unequal bytes. Its first wrong operand is the `lea` displacement at +0x2a. The union address is ESP+4, while the oracle uses ESP+0xc. Deleting moveweapons changes the positions of downstream publics. All four NEAR bodies retain identical OMF code payloads and complete verifier reference records on both snapshots. [Current peer payload comparison](refresh/runs/game_actors/remove/peer-payloads.json). All other current ACTORS publics retain their results. Moving the storage, taking the address through the union or either member, and separating the narrow read failed to recover all homes in the 36 placement and 90 address/read controls. Dropping the unsafe cast and reading a full-width distance changes the projectile comparisons as well. **GAME `ifhitbyweapon`.** The later Duke FUNCT.H declares `short ifhitbyweapon(short)`, as does the reconstructed ACTORS definition. At GAME’s sole call, the oracle at extent +0xb58 calls it and immediately executes `test eax,eax` at +0xb5d. The existing wide declaration emits the same test. The short-return alternative emits `test ax,ax`. The 14,016-byte extent stays fixed, byte differences fall from 9,324 to 9,167, and fixup diagnostics fall from 754 to 720. This is a false lead with independent instruction-level evidence. ## Which STRICT spellings are interchangeable?

**PLAYER.** Duke’s later PLAYER.C declares hitspr, hitwall and p in that relative order. Bringing those three current short locals together keeps the complete 1,728-byte shoot, the five STRICT publics (3,724 B), and the 120-byte verified data segment. The 15,692-byte processinput has one fewer raw byte difference (10,512 to 10,511), with 621 fixup diagnostics in both builds. An independent normalized-block lookup identifies the candidate +0x1f44 LEA and oracle +0x1f51 LEA with the same output stack address, ESP+0xf0. Aligning the surrounding instruction sequences accounts for all 18 changed operands. Five gain their oracle home and six lose it, including three uses in each of the two player-result groups. This rules out treating the single raw-byte delta as a fix. Only two of 72 local-order controls and two of 108 scope controls passed the raw improvement filter. Their canonical DOS builds reproduce these losses. [Unique-block comparison](runs/game_player/shot-word-group/processinput-aligned.json) · [All 18 operands](runs/game_player/shot-word-group/processinput-context.json) · [Order controls](screen-processinput/orders.json) · [Scope controls](screen-processinput/search.json).

**MENUES.** The byte-shade proposal described in TRADES.md is already the baseline at 08738fd. It has 10/11 STRICT, 8,634 bytes. No new gain is claimed for its historical improvement from 395 unequal bytes to four. Reverse lookup finds 441 bytes of shared normalized blocks in the current caller and no unmatched block with a STRICT donor. Removing the lowercase glyph temporary leaves six differences each in menutext and draw_and_probe. A K&R helper definition reproduces the entire DOS object. None of 140 tests of typed and old-style formals, capture order and local widths improved the four-byte caller while keeping every STRICT public. [Current reverse lookup](menu-reverse.txt) · [K&R DOS control](runs/game_menues/kr-helper-cursor-s-t-y-x/dos.json) · [Search results](menu/search.json).

**Other alternatives.** In GAMEDEF, conventional i, j, k declaration order in parsecommand yields the same DOS object. In PREMAP, assigning literal zero to the weapon ownership bytes in newgame also yields the same object. In SOUNDS, using the library’s void-pointer memory-hook declarations is byte-neutral. Removing the padded strings as a group costs three SOUNDS publics their CONST proof without fixing spritesound. Removing the empty/menu NUL spellings in MENUES costs two proofs. In ACTORS, separating the ammo increment and addweapon call leaves 14 publics STRICT but grows moveactors by 64 bytes in the original snapshot. The switch score deteriorates from 3,135 to 8,812 differences. These cases distinguish historical ambiguity in a STRICT function from an actual constraint on a NEAR caller.
