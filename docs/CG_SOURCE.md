# Watcom 9.5 GA code generation on i386

Two passes can choose a register for the same C expression. The global allocator assigns registers or memory to program values. Later, the x86 load/store pass can introduce a register for an individual memory operand. In the December ENGINE candidate, the latter pass selects EBP for the left column in `drawmaskwall`. In ACTORS it selects EBP for the arm-piece floor height. A trace ending at the global allocator misses both decisions.

## Evidence and coordinates

**CONFIRMED-FOR-9.5** covers the stated property on the measured build. **DIFFERS** identifies a specific contrary prediction, with the distinguishing observation. **UNTESTED** identifies an internal rule for which the available observation cannot discriminate between implementations. A STRICT function establishes the machine result. Specific breakpoints or controlled source pairs establish which pass produced it.

## The three sorts

1. **Candidates, before bit allocation. CONFIRMED-FOR-9.5.** `cg/c/dataflo.c:AddTempSave,AllocBefore,RoughSortTemps` scans every optimized operand and result. For an indexed operand it counts the index and resolves the temp to its master. A qualifying reference with a conflict contributes `Weight(1, block)`. `cg/c/regsave.c:SetLoopCost,Weight` and `cg/h/savings.h` scale by optimization bias and cap the depth. GAME's measured sequence is 1, 20, 400, 8,000, 160,000, 3,200,000. Do not apply 20 universally to every speed/size profile. RVA 3ce14 sorts flag 0x100 clear first, then conflict present first. With two conflicts it compares unsigned savings descending. Without conflicts it compares signed IDs descending. Equal savings have no ID tiebreak. Earlier IR replay reproduced 1,196 observed savings in seven SECTOR passes. Source levers are the number, block and identity of *surviving* reads/definitions.
2. **Conflicts, after instruction expansion. CONFIRMED-FOR-9.5** for priority and the constant adjustment. `cg/c/regsave.c:CalcSavings`, `cg/h/savcode.h,savcache.h`, `cg/intel/c/x86regsv.c:InitWeights,ConstSavings,WorthProlog`, `cg/c/regalloc.c:AssignConflicts,ConfBefore`. This is a fresh cost calculation. It weighs savings from definitions, uses and indices against necessary loads/stores, with loop weighting and CPU/time/size costs. Held and unusable ranges can score zero. Constant caching then favors ordinary conflicts by adding the largest calculated constant saving to newly calculated positive ordinary savings. RVA 538a8 calls the raw calculation, 538c5 calls the constant pass, 538ca sorts. In checkhitswitch both t116 and t117 have **160 raw + 404 constant adjustment = 564**. The positive adjustment agrees for every applicable ordinary conflict in both passes. STRICT stopsound is a zero-adjustment control. ConfBefore at 53951 compares only unsigned savings descending. **UNTESTED** for every raw savings-table entry and all CPU models. Receipts in `build/workers/owcg/savings/`.
3. **Homes, after colouring. CONFIRMED-FOR-9.5** on the checked profiles. `cg/intel/c/x86temps.c:TempAllocBefore` implements the comparator. `cg/c/temps.c:AssignOtherLocals` calls it. RVA 4d5bc compares flag 0x200 set first, then smaller size, then larger alias offset only within the same ID. Separate equal-size IDs stay comparator-equal. The descendant flag name is `USED_AS_FD`. **DIFFERS** for the alignment exception. The descendant reverses the flag preference when `CurrProc->targ.sp_align` holds. The complete 9.5 comparator at 4d5bc–4d5f6 reads only the two records. Its flag branch is unconditional with respect to procedure alignment.

All three call the same list sorter. `cg/c/cgsrtlst.c:DoSortList,ShellSort` puts pointers in an array, starts with the list length, and alternates floor-halving with an extra one. Each gap repeats until a sweep makes no exchange. A third record can move two equal-priority records past one another. The 9.5 ordinary path at 4c3c5 reproduces **20 candidate, 22 conflict and 10 home sort outputs** on the ten DOS-correlated traces rechecked here, including the three STRICT controls. **UNTESTED** for the out-of-memory merge fallback. Exact ranks require the complete input list. See `build/workers/owcg/audit.json`.

## Registers, spills and stack placement

**Register choice. CONFIRMED-FOR-9.5** for eligible-leaf selection. The operative file is `cg/c/regalloc.c`. The file named `cg/c/regassgn.c` ends after its header in this checkout. `regtree.c:BuildNameTree,BuildRegTree,Intersect` constructs whole/high/low restrictions from instruction-specific choices and aliases. `regalloc.c:NeighboursUse,TooGreedy,GiveBestReg` excludes overlapping live/zapped registers and combinations that would deprive an instruction of a required index or register. It scores allowable registers by moves or matching result/operand forms that could be eliminated. Equal scores retain the first eligible register unless only the challenger overlaps the requisite previously given set in full. The winner is subject to prologue cost unless required. Successful allocation rewrites operands and updates liveness for later conflicts. An unreferenced whole can be allocated by parts. All 1,302 scored leaves replay the observed pre-cost winner from eligibility, score and previous-use flags. Another 281 leaves had no scored candidate in these traces. This check does not reconstruct the scores from C. See `tools/cg95/cgtrace95.py` and `build/workers/owcg/audit.json`.

**A scoring difference matters in checkhitswitch. DIFFERS.** The descendant's Intel non-MOV arm in `CountRegMoves` at lines 485–496 gives half-size credit when a register operand overlaps the proposed destination. For the archived 9.5 case-405 conversion, the result is the four-byte t116, operand 0 is CX, and ECX is eligible and already used. Its measured ECX score is **zero**, as is EAX's. Transplanting that overlapping-conversion bonus would incorrectly predict credit for ECX. The scale t117 subsequently scores EAX and ECX at two apiece. Other overlap and partial-register cases require independent tests.

**Spilling. CONFIRMED-FOR-9.5** for interference spill and its consequence. `GiveRegister,PutInMemory,InMemory` in `regalloc.c` take the no-colour/cost paths. A required index or segment may be split into a short-lived temp on the next expansion pass. Ordinary spills can become memory operands. Storage still depends on later references, lifetimes and home assignment. A blocked leaf, a zero-savings conflict, and a leaf failing a save/restore cost test can all lead to memory. In ACTORS, changing the visit order of the tied velocity conflicts changes which value spills. STRICT `stopsound` demonstrates the opposite path, a changed index width and an actual register assignment. **UNTESTED** for every retry and cost-veto path.

**Stack storage. CONFIRMED-FOR-9.5** for survivor order, shared slots and final frame/displacement data. In `temps.c:AssignTemps` parameters propagate and pushable locals are processed before remaining locals. `AssignOtherLocals` sorts a list or active prefix, walks remaining unallocated non-alias masters requiring storage, and calls `AllocNewLocal`. In v2 a size rounded to register width is reserved. A single-block non-addressed value with a usable interval can take the first sufficiently large slot whose recorded live intervals do not meet it. Multi-block/addressed cases can require a dedicated location. Dead or sole removable uses can disappear. `PropLocal` propagates storage to aliases. Intel `SetTempLocation` grows the local area downward, and frame fixup translates the internal location to a final displacement. The 9.5 home and frame hooks at 3eff9 and 5e177 distinguish all sorted names from actual occupied homes. STRICT moveweapons has a four-byte reservation for an address-taken short. The GAME home-swap witnesses and SECTOR scope controls show how equal rank, shared identity and actual slot size have separate effects. **UNTESTED** for the entire first-fit/reuse implementation on every path. Source-level lifetimes and address-taking matter only to the extent that optimized uses survive.

## The x86 load/store pass and scheduler

**CONFIRMED-FOR-9.5.** After global allocation, `cg/intel/c/x86ldstr.c:Enregister,FindRegister,LoadStoreIns,LdStAlloc` splits eligible operations with a memory operand into load/register-operation or register-operation/store pairs. Byte, word and dword scratch-register lists have separate rotating positions. The exclusion mask combines live hardware registers, zap masks and an existing register result. Each successful transformation can alter liveness and the position for a later operation, even in a different basic block. Subsequent register-value propagation, compression and scheduling can hide the scratch choice in the final instructions.

**DIFFERS.** At 5a0a7, 9.5 clears the three positions and returns early for size bias >50 or CPU below 486. V2 still runs a size-preferring mode in those cases. In 9.5 `FindRegister` at 59f13 initializes a new list at its first entry, advances *before* testing, scans cyclically past exclusions, and retains the accepted pointer. V2 tests the current entry first and retains its successor for the next visit. Its source explicitly dates the rewrite to 2006-04-25. The difference is especially visible at initialization. For a list already in use the two representations can yield the same sequence. The saved 9.5 state means “last accepted” in the measured cases.

The independent scan predicted **151/151** ACTORS decisions for current moveexplosions, **152/152** for its earlier source, **152/152** for a single-local source change on the current TU, and **55/55** for stock drawmaskwall, including failed scans. For the ACTORS floor operation the mask and operand were identical in both versions. Only the incoming dword-list position changed. The final floor register is traceable to one extra eligible multiply in block 66. For ENGINE, ESI is excluded before the scheduler subsequently reorders the quotient copy and column load. These are different source problems. See `build/workers/owcg/postpass/{current,previous,angle-stage,mask}/rover.json` and the stage snapshots alongside them.

**Scheduling. CONFIRMED-FOR-9.5** for the location of this reorder. The stock block at the scheduler guard (3f1d8) still has the quotient copy before the xb1 load. At 3f1f9, after the scheduling call and live-info update, the order has reversed and the registers are identical. The 9.5 driver disables live information around 40a44 and calls the liveness updater before restoring the flag. **UNTESTED** for identity of all DAG edges, costs and tie rules. V2 `cg/c/inssched.c:BuildDag,DataDependant,ImplicitDependancy,StallCost,ScheduleIns` builds a block-local dependency graph with register, memory, flag and implicit constraints. It schedules backward from ready nodes, considering stall cost, DAG height, index adjustment, FP stack and instruction order. It cannot exchange instructions across arbitrary C statement boundaries if their optimized operations still depend on each other. The STRICT calcwalls example anchors final ordering. A schedule observed after two independent loads gives insufficient evidence to reconstruct the original source order.

## Reproduction

From the repository root, run the worker scripts with `python -B`, one at a time. `baseline.py` records DOS controls and SemIR classifications. `audit.py` verifies the hashes of archived traced objects, replays all three sorts, and checks scored leaf choices. `prepass.py` and `savings.py` use fresh matched DOS controls. `postpass.py` records 15 snapshots each for current and older ACTORS, `rover.py` replays the actual ring inputs, and `mask.py` observes the unmodified ENGINE function and compares it to its archived DOS code and verifier references. These scripts only observe compiler execution. The source trials and their whole-unit verifier results are described in the companion report. No debugger-produced object is an integration candidate.
