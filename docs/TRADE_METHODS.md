# Testing a Watcom match that moves another function

1. **Freeze both sides of the comparison.** Save the complete source, its headers, the original profile and an ordinary full-unit DOS object. Rebuild the reported edit against that snapshot. Then reapply just its source hunk to the current copy. A source hash alone misses header drift. JNG's two-build ledger treats a disagreement as evidence and records losses by name. Here the two constraints are the standalone public and its users in the same DOS image. NT is a fast probe of the same compiler family. [JNG two-build method](D:/Prog/jng_recon/docs/two_build_method.md) · [JNG compiler rules and their scope](D:/Prog/jng_recon/docs/codegen_rules.md)

2. **Classify the first changed operand.** For a relative branch, decode both destinations as public plus offset. Subtract the movement of the source instruction from the movement of the destination. In ENGINE this accounts for all 13 changed branch operands, including reverse jumps from distant functions. For a carried table, identify the dispatch owner, carrier, bound entry, largest oracle destination and actual candidate span. For an inline expansion, compare the helper and each caller's own colours and frame homes. CyberStorm's shared-tail and carried-table examples distinguish these three experiments. [CyberStorm levers](D:/Prog/cyberstorm_recon/docs/levers.md)

3. **Reduce definitions while preserving declarations.** JNG replaces bodies with declarations, retains order, headers and data, then rebuilds after each deletion. Its final deletion witnesses apply only to the frozen input. The local DOS experiment does this twice, with the wide and byte shade formals. Removing the body of `probe` changes the caller by about 400 bytes. Keeping `probe` recovers the instruction stream. Removing the following `menus` can still cost the final byte and its extent proof. Preserve the oracle verdict, raw public span, fixups and proof messages as separate observations. [JNG island tool](D:/Prog/jng_recon/tools/island.py) · [JNG measured limitations](D:/Prog/jng_recon/docs/islands.md) · [Local reduction driver](islands.py)

4. **Test two predictions independently.** Rayman's causal register pairs a fixed-body negative control with an edit known to affect allocation. Its inverse-allocation work distinguishes changing a sort order from changing the set of live records. Here identical ceiling colours and bytes survive a change in the next function's extent. Conversely, the public `gametext` survives an edit that moves the same named glyphs in its callers. Record named homes, final frame and verifier output for both. GCC, Watcom 10.6 and 9.5 have separate evidentiary records. [Rayman causes](D:/Prog/rayman_recon/docs/CAUSES.md) · [Rayman blockers](D:/Prog/rayman_recon/docs/BLOCKERS.md) · [Rayman matching procedure](D:/Prog/rayman_recon/docs/MATCHING.md)

5. **Promote only evidence the full unit retains.** Kegg compares extent, bound references and instruction islands separately, then reruns verification at promotion. Record existing STRICT losses by function and bytes, and separately name any worsened NEAR function. Record a finite failed family with a concrete reason to reopen it. Original ABI evidence, a new donor, or a source change that moves the missing home without disturbing the other live homes qualifies. A diagnostic allocator replay establishes a compiler decision, while a stock DOS build establishes the source result.
