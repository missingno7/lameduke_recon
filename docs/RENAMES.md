# RENAMES: prioritized semantic rename plan (semantics worker, 2026-11-26)

Generated by `build/workers/semantics/render.py` from `semantics.json` (itself built by `gen.py` from config/, src/, Ken's Build sources, Duke3D 1.5, raynorpat's rebuild, the CON/MAP data and the per-unit research in `parts/`). Nothing under src/ or config/ was edited. Confidence: PROVEN-BY-BYTES / STRONG / HYPOTHESIS.

## How to apply (integrator)
- A rename never changes code bytes by itself, but the verifier binds by name: rename in `src/` and in `config/symbols.json` (same address) in one commit, then run `python tools/gate.py`.
- Function, parameter, local, struct-field and macro renames are layout-neutral. Only defined, uninitialized objects (globals and statics in _BSS) are sensitive: Watcom 9.5b emits _BSS by size bucket, then later 22-slot symbol page first, then name hash (tools/bssrule.py).
- **New fact (derived from bssrule.name_hash, checked on 2,000 random names):** `h = (h*16 + c) & 0xfff` keeps only the last three characters, so the hash is `(256*c[-3] + 16*c[-2] + c[-1]) mod 4096 mod 211`. A rename that keeps the last three characters (svel->vel, player_svel->syncvel, demo_tics->recsynctics, pending_bits->osyncbits) can never move anything. Otherwise only same-bucket neighbours on the same page whose hash order flips matter.
- Each global rename below carries a verdict from `bss_checks` in semantics.json: global.c is checked exactly against `build/workers/dataown/global_stream.json` (the stream that reproduces the oracle); other units with a conservative same-bucket hash-order test (pages unknown -> MUST-TEST when an order flips).
- `_DATA`/CONST initializers are laid out in definition order, so renaming them (scan_ascii, quote_text) is neutral.

## Priority 0: atomic groups and hazards

All renames of this group must land together, in every unit (player.c, game.c, premap.c, gamedef.c, actors.c, sector.c, menues.c headers).

### 0.2 Player record: previous-tick position vs respawn point
Offsets 0x1a/0x1e/0x22/0x42 are the previous-tick position and angle (Duke 1.5 and Ken `oposx/oposy/oposz/oang`); global.c calls them previous_x/y/z/previous_ang. Offsets 0x2a/0x2e/0x32/0x40/0x46 are the respawn point (our current oposx/oposy/oposz/oang/ocursectnum). Rename both sets in one step (respawn set first, to startposx/startposy/startposz/startang/startsectnum, HYPOTHESIS names), or the same field name will denote two offsets across units. Field renames are byte-neutral.

### 0.3 _BSS-sensitive renames (do not apply blindly)
- `randomstash -> global_random` (global.c): moves 2 objects if global.c keeps its declaration order (randomstash 0x9a730->0x9a732, neartagsprite 0x9a732->0x9a730). Options: keep the old name, pick a name whose last three characters keep the hash order (e.g. end it in "ash"), or regenerate the COMPILER_STEERED global.c with `build/workers/dataown/gen_global.py` after renaming in global_items.py and verify.
- `brace_depth -> num_squigilly_brackets` (src/game/gamedef.c): hash 61->86 flips order against checking_ifelse in the same size bucket; must be tested with match.py (_BSS layout line) or keep the current name.

### 0.4 Header views that disagree with the code (field renames, byte-neutral, fix first)
- `src/game/sector.h` playertype: 0x93/0x94 named the wrong way round (0x93 = scuba_on, 0x94 = jetpack_on; F5 plays JETPAKON/JETPAKOF), the first two inventory bytes swapped, 0x96 called nightvision_charge.
- `src/game/gamedef.h` playerstate: 0x48 is look_ang (not horiz), 0x5a is jumping_counter (not poszv), 0x52 is rocket_ammo (rammo), 0xab is the shooting/muzzle byte.
- `src/game/actors.h` playertype: 0xac-0xaf are max_squashed/actors_squashed/max_actors_killed/actors_killed (not kills_left/kills/total_kills/turret_kills).
- `src/game/player.h` weapon_delay[13]/weapon_slot are really the FTA quote timers fta[13]/ftq (13 = number of quote_text entries; Duke 1.5 fta/ftq).
- `src/game/menues.h` menu_player: game_mode@0x8a -> gm, unknown_8b -> weapon_clock, episode@0x8e -> volume.
- Aliases for one object: `disable_armor` is userdefs.debug (/d debug flag), `facing_sprite` == `camerasprite` == userdefs.camera, `transition_zoom`/`gamepaused` == userdefs.paused, `MusicToggle` macro in sounds.c is SETUP.DAT option[2], not userdefs.music.
- Engine `BUILD.H` names wall fields nextsector1/nextwall1; `src/game/build_v5.h` calls them nextsector/nextwall. Ken's Oct-94 spelling is nextsector1/nextwall1 (v5 has a second pair nextsector2/nextwall2).
